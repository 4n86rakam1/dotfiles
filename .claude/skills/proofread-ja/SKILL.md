# 日本語校正

## 原則

- 意味を変えない。整えるのは表現であって内容ではない。書き手の判断・評価・感情を薄めない
- 日記や回想は口語で書かれる。技術文書の基準を当てない。記録としての価値は読みやすさより当時の言葉づかいの保存にある
- textlint の指摘には誤検出が混ざる。そのまま採用しない

## 1. 機械チェック

```bash
proofread <path>
```

パスに応じて設定が切り替わる。`diary`, `misc`, `journal` を含むパスと `recollection.*` は口語扱いになり、助詞の重複・句点・語の連続・AI 誇張表現を見ない。それ以外は技術文書のフルセットを当てる。明示するなら `--casual` を付ける。変更分だけ見るなら `--diff`。

## 2. 誤検出の判別

以下は機械が誤って指摘しやすい。採用前に文脈を確認する。

- `ja-no-successive-word` — 「一つ一つ」「つどつど」など、反復が正当な表現
- `prh: のことを => を` — 「自分のことを」など、省くと不自然になる場合がある
- `no-doubled-joshi` — 一文に同じ助詞が 2 回あっても、係り先が違えば問題ない
- `no-ai-hype-expressions` — 「完全に」は口語では誇張表現ではない

## 3. 文体方針への適合

`~/.claude/CLAUDE.md` の日本語出力方針に沿っているか見る。textlint で機械化できない部分を担う。

- 常体 (だ・である)。です・ます が混ざっていないか
- 体言止めを使えるか
- 和語より漢語・熟語
- 冗長表現。〜することができる → できる、〜という → 省略、〜に関して → について、〜のことを → を、〜であるため → のため

## 4. 論理の確認

表現の前に内容を見る。

- 主語と述語が対応しているか
- 接続詞が論理関係と合っているか。「しかし」で順接をつないでいないか
- 一文に主張が 2 つ以上入っていないか

## 出力形式

指摘ごとに行番号・原文・修正案・理由の 4 点を書く。機械チェックの指摘のうち採用しなかったものとその理由も 1 行ずつ挙げる。誤検出の傾向が分かれば設定を調整できる。

## 設定の調整

誤検出が繰り返し出るルールは `~/.config/proofread/textlintrc.json` または `textlintrc.casual.json` で無効化するか、`~/.config/proofread/prh.yml` に例外を追加する。文中で一時的に抑制するなら `<!-- textlint-disable ルール名 -->` を使う。
